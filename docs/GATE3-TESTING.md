# Gate 3 test plan

Gate 3 passes when an executable built without plugin definitions loads verified JARs at run time, uses the right defining loader for every lookup and call, and recovers from a rejected registration in the same process. Run the Java behavior cases against OpenJDK 21 and Catty. Check Catty's archive policy, transaction state, and engine traces directly. [Gate 3 implementation specification](GATE3.md)

## 1. Runner and fixture layout

Add `tests/gate3.py` and fixtures under `testdata/gate3/`. Reuse the toolchain checks, subprocess logging, generated Go inspection and class-file patch utilities from the existing suites. The runner supports `--java-home`, `--prepare-only` and `--case NAME` with the same intent as the Gate 2 runner. A full run requires every case and fails for a missing fixture, result, trace or required assertion. Store artifacts under a printed temporary directory.

Use separate directories for the shared application classes, compile-only API stub, OpenJDK adapter, each plugin version and each malformed variant. For an end-to-end case, follow this order.

1. Compile only the application and its shared API classes with `javac --release 21 -g` against the compile-only stub. Check the binary names with `javap -v`. Build the Catty image in the required modes and save its SHA-256, build report, generated Go and decoded image class list. Assert that the plugin JAR paths and plugin build output directories are absent at each image build, and that the image and report contain no plugin definitions, API stub definitions, or plugin content. Binary name strings used by `Class.forName` may appear in the image.
2. Compile each plugin version against the application output and stub, using an isolated output directory so a previous sibling's classes cannot supply a dependency. Package only that version's classes into its JAR. Keep each JAR's digest and entry list. Assert class-file version 65.0 and use `javap` to pin important opcodes, symbolic owners, constant-pool indices, and call-site PCs. Create negative variants with a deterministic packaging or class-file mutation.
3. Run the Java cases with OpenJDK 21 and `-Xverify:all`. Use a test-only implementation of the custom API that accepts the same bytes, stages them into a temporary JAR, and creates one standard parent-first JAR loader per successful registration. Give the oracle the same application class files and JAR bytes as Catty. Keep plugin JARs off the oracle's system classpath. Use standard `Class.forName`, reflection and Java checks in the fixture. Pin the expected markers, exception classes, throwable identity checks and side-effect order independently of the adapter. The Catty admission-policy cases exercise Catty directly.
4. Run the prebuilt Catty binaries with external JAR paths supplied as Java arguments. Compare exit status and stdout bytes for successful differential cases, and require empty stderr. For uncaught Java cases compare the specified status, exception binary name and ordered application frames without comparing VM-specific diagnostic formatting. Check SHA-256 again after the runs. The same image can run against multiple replacement JARs.

`--prepare-only` checks corpus compilation, JAR construction, bytecode assertions and reference outcomes without building Catty. A full run additionally enforces the application-build-before-plugin ordering in a fresh directory. Run each positive Java case with an all-interpreted image, a mixed policy, and a forced-AOT image, using image methods that the AOT emitter supports. All plugin methods must be interpreted in every run. Create a distinct image fixture containing `irem` to verify Gate 2 image fallback and forced-AOT rejection under the new profile.

## 2. Required Java cases

| Case | Fixture and action | Expected result |
| --- | --- | --- |
| `late-override` | Image `api.Base` implements `api.Step`; both expose `value(Box)`. Call twice through one `invokevirtual` site and twice through one `invokeinterface` site on an image receiver. After those calls, look up `ext.Worker` by string and use its public static factory to obtain a late subclass. Alternate old and new plugin receivers at the same sites. | The prescribed return sequence, callback count, and cache transitions below. The ordinary object crossing includes the exact same image-owned `Box` reference. |
| `name-lookup` | A plugin contains dormant public static `magic()` returning `73`; it has no static callers. The application also contains a public static method reachable only by name. Pass their names as arguments. Call `Class.forName(name, false, loader)` and `getMethod`, then invoke each method. Try the plugin name through the application loader and the wrong sibling first. | Wrong loaders throw `ClassNotFoundException`. Lookup and method discovery leave initialization markers absent. Invocation returns `73` for the plugin method and the pinned image value. Traces show the plugin target interpreted and the image target in its selected engine. |
| `parent-first` | Supply a plugin with different copies of an application class and a shared interface. Resolve them through the plugin and application loaders. Register a grandchild using an already published plugin parent and a second plugin with null parent. Include an independent class in the null-parent JAR. | The delegated mirrors equal the parent's mirrors and the parent implementations run. The child's unique classes can implement the parent interface. The grandchild can resolve its parent and application types. The bootstrap-parent plugin can see `Object` and its own class, and an application-only lookup throws `ClassNotFoundException`. Application and sibling lookups of a child-only class also fail. |
| `loader-identity` | Register identical bytes twice. Each JAR defines `ext.Worker`, a same-named array type through allocation, and a static counter. Make fresh and retained instances. Cross-cast by reflecting on plugin helpers that run `checkcast`, `instanceof`, array stores and array-literal lookups. | Different loader handles, class mirrors, class and array identities. Delegated API, primitive and primitive-array mirrors are shared. First counts are `1, 1`, and calling the first instance again returns `2`. Cross-sibling `instanceof` is false, cast throws `ClassCastException`, and store throws `ArrayStoreException`. Both remain assignable to the shared API. |
| `replacement` | Load versions A and B from different JARs with the same names and API. Invoke on the old object, rebind the application's active reference to B, then invoke on both old and new objects at one call site. | B returns its new result. A retains its old method, statics and identity. Its method remains callable without reopening A's JAR. The trace distinguishes the two targets by loader ID. |
| `access` | Place image and plugin helpers in the same textual package. Compile against an app class with package access, then run the helpers through the child loader. Exercise a protected call on another instance of the plugin subclass. Include a package-private method on the base and a same-signature child method. Add a same-loader nestmate control. | Cross-loader package access fails with `IllegalAccessError`. The protected call works on the subclass receiver. A call resolved to the package-private image declaration selects the image method. The same-loader nestmate access works. Check invalid protected receivers and nest claims during admission. |
| `reflection-identity` | Define `Worker.accept(ext.Token)` and an array overload in two sibling loaders. Discover the parameter mirrors by each loader. Use Class.getMethod with the correct mirror and then the sibling mirror. Invoke using correct and wrong sibling receivers and arguments. Include a covariant bridge case. | Exact parameter identities select the intended method. A sibling parameter mirror yields `NoSuchMethodException`. Invalid receivers or arguments yield `IllegalArgumentException`. Covariant lookup uses the defining loader of the candidate return class. |
| `crossing-throw` | Pass an image-owned throwable and mutable `Box` to a plugin method. Have the plugin call an image callback that mutates the box and throws that original object. Run a direct virtual call and a reflective call. Compare the caught exception and reflected cause with the input by reference. | One mutation per call. Direct catch sees the original object. Reflection produces `InvocationTargetException` with that object as its cause. Mixed/AOT-image traces show AOT → interpreter → AOT and the same throwable ID from callback to compiled catch or reflection wrap. |
| `initialization` | Register a JAR with an initializer that mutates an image counter. Look up the class with `initialize=false`, get a method and allocate an array of the class through a separate plugin factory. Then call `Class.forName(..., true, loader)` and make a static call. Include a second class whose initializer throws an image-supplied non-`Error` object and load the same JAR under another loader. | Registration and passive operations leave the counter at `0`. Active use applies constants, initializes the superclass first, and runs each initializer once per defining loader. The first failure yields `ExceptionInInitializerError` with the original cause, and later uses yield `NoClassDefFoundError`. The sibling loader's first use runs its own initializer. |
| `deferred-linkage` | Give two loaders identical referencing bytecode. One has an application dependency missing a field and method, and the other has the expected version. Include a call to a missing class using only a lazily resolvable symbolic method reference. Call a good entry point first, then repeat each bad call twice and interleave calls into the valid sibling. | Admission and the good path work. First execution and repeats produce the corresponding `NoSuchFieldError`, `NoSuchMethodError`, or `NoClassDefFoundError`. The valid sibling keeps returning the expected values. Catty runtime tests prove the failed resolution entries are sticky and scoped to their referring runtime class and constant-pool index. |
| `uncaught-plugin` | Throw from a plugin method through image frames without a catch. | Exit status `1` and the expected Java throwable and ordered plugin/image frames. Catty trace frames unwind in the same order on one logical thread. |

### Pinned late override sequence

Use one shared `Box` initialized to `0`. `Base.value` increments it by `1`, plugin A increments by `10`, and plugin B increments by `20`. Each implementation calls the image method `Box.add(int)`. It increments a callback count and returns the updated value. The image wrappers each have one dispatch site, so the site stays constant throughout.

| Operation | Expected values | Expected compiled cache |
| --- | --- | --- |
| Virtual call on base, twice | `1, 2` | Miss, hit |
| Interface call on base, twice | `3, 4` | Miss, hit |
| Register A and call it twice at the original virtual site | `14, 24` | Miss, hit |
| Call A twice at the original interface site | `34, 44` | Miss, hit |
| Register B, call B at the original virtual site, then A | `64, 74` | Miss, miss |

The final box is the object created by the image and its callback count is `10`. Pin an stdout marker immediately before the first registration. Assert that the trace first names an image declaration and target, then an image declaration and interpreted plugin override, then the correct original target after switching back to A. The declaration identity is constant within each call site. The mixed policy keeps both wrappers and `Box.add` compiled and designates a separate image helper interpreted. In the all-interpreted image, record the same result and general selector targets without requiring cache events.

## 3. Admission and recovery tests

Run these cases through the Java registration intrinsic where supported by the fixture. Also check classification and boundaries in Go with smaller injectable limits where practical. Limit overrides belong to tests. Use per-case archive contents that isolate the named failure. Verify the first valid class sorts before the entry whose rejection is expected.

| Group | Required cases | Assertions |
| --- | --- | --- |
| ZIP integrity and names | Non-ZIP, truncated central directory or entry, bad CRC, duplicate entry, file/directory conflict, empty class set, noncanonical names, disallowed ZIP file types, encryption, unsupported compression | Stable `ARCHIVE` for structure, names and transport errors. No publication or Java initializer. |
| JAR policy | Named module, multi-release manifest and versioned path independently, mixed-case and folded manifest attributes, nonempty `Class-Path`, sealed package, signature metadata, reserved bootstrap and Catty API definitions | Stable `PACKAGE` and feature or entry location. Assert no dependency is opened or extracted and no alternate class is selected. |
| Class structure and profile | Entry/name mismatch, malformed/truncated class, unsupported major or preview version, unsupported opcode or bootstrap constant, synchronized or native member, unavailable bootstrap method, class under `META-INF` | Expected `CLASS_FORMAT`, `PROFILE`, or `PACKAGE` per the specification. Assert class and method/PC fields when available. A shadowed class still receives its structural and profile checks. |
| Verification and linking | Invalid stack-map and category-two local use, invalid exception handler state, missing superclass/interface/catch type, invalid superclass or interface kind, final superclass, cyclic hierarchy, cross-loader or nonreciprocal nest claim | `VERIFY` or `DEPENDENCY` with the expected declaring class and location. Force OpenJDK to link fixtures that violate Java verification rules and assert the corresponding Java failure. |
| Protected receiver | Compile `Probe extends Base` in Base's textual package with a method that calls a protected Base member on a receiver declared as `Base`. Put Base in the application and Probe in the plugin. | Catty rejects with `VERIFY`. OpenJDK reports `VerifyError` when the oracle uses `Class.forName(..., true, loader)` on Probe. |
| Limits | Compressed and expanded bytes, entry size/count, class count, hierarchy depth, verification work, published loaders and cumulative class bytes. Include deflate, and a rejection after partial budget use. | Just below and exactly at the cap are accepted. The next unit produces `LIMIT`. Refused transactions consume no retained quota. The opened file's actual read limit applies even when an earlier size check reported less. |
| API misuse | Null JAR/name/path, nonexistent and nonregular source, plugin-defined call to `readJar`, foreign or fabricated handle in a Go-level test | Exact API throwable types. Scope accepts a runtime-owned plugin parent and the bootstrap null sentinel. A failed read leaves registration state untouched. |

For the mandatory `rollback` integration case, warm an existing image call site and invoke a valid plugin. Register a JAR with a valid first class and an invalid later class. Catch `PluginAdmissionException` in Java and print its code. Confirm that the original image and plugin objects still work and the existing class cannot find the rejected definition. Register corrected bytes with the same candidate class names and invoke the class that had been staged first. Require a rejection trace without a loader ID or candidate definition/initialization event, followed by successful publication and execution in the same process and on the same logical Java thread.

In Go, snapshot the registry, loader IDs and quotas, parent initiation records, relevant cached successes and failures, array intern table and existing static state before a failure injected after verification and before commit. Compare the snapshots after rejection. Mutate the caller's admitted byte array after a successful registration, then materialize a class and assert its original bytes were used. Add a bounded fuzz target for the archive/staging entry point with seed cases for stored, deflated, malformed and budget-boundary inputs. A fuzz invocation must return a controlled diagnostic or checked definition set without a panic or a published loader.

## 4. Build, trace, and standalone checks

- **Profile and packaging.** Check the Gate 3 image/report pair, flag, exact added inventory, and limits. Reject mixed profile/ABI pairs and an unknown profile or ABI before startup or `main`. Check disabled-profile builds still emit Gate 2 and reject references to the new bootstrap API. Keep missing-bootstrap and failed-rebuild checks that preserve a prior executable. Check opted-in `--mode aot` stays strict for image methods.
- **Generated Go and traces.** Use the Go AST inspector to confirm that the compiled wrappers invoke the shared dispatch path at the inspected bytecode offsets. Correlate `plugin_admission`, `class_define`, initialization and dispatch events by loader ID, archive digest, caller and original PC. Assert no plugin class is defined before registration and that registration does not execute a plugin method. Check balanced frames, exact crossing order, matching throwable IDs, and one process and logical thread per run. Exercise resolution with the same class names, descriptors and CP indexes under distinct loaders.
- **Standalone run.** Build the mixed executable with image classes and the stub in separate locations. Move the executable and the late JARs to an otherwise empty directory. Hide the original class directories, adapter and stub. Run by absolute path with empty `PATH`, unset `JAVA_HOME` and `CLASSPATH`, and external JAR paths. Require the same stdout, status and trace relationships, with no changes to the executable digest.
- **Regression.** Run the complete Gate 2 corpus against default builds, including its Gate 1 regression. Run the supported positive corpus with Gate 3 enabled as well to exercise shared runtime helpers under the new profile. Execute Go tests and vet. Preserve current Gate 2 wrong-profile, wrong-ABI, generated code and standalone checks.

## 5. Commands and completion evidence

Run from the repository root with Go and OpenJDK 21 available. The Gate 3 runner and fuzz target are implementation deliverables.

```sh
go vet ./...
go test -count=1 ./...
python3 -B tests/gate3.py --java-home /path/to/jdk-21 --prepare-only
python3 -B tests/gate3.py --java-home /path/to/jdk-21 --case late-override
python3 -B tests/gate3.py --java-home /path/to/jdk-21
go test ./internal/admission -run='^$' -fuzz=FuzzStageJar -fuzztime=30s
python3 -B tests/gate2.py --java-home /path/to/jdk-21
```

Include the standalone run and full Gate 2/Gate 1 regression logs. Publish the handoff in `out/gate3/EVIDENCE.md` after the full Gate 3 check passes.
