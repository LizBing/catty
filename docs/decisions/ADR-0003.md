# ADR-0003: 执行引擎 = 解释器地基 + Go 源码发射 AOT 主路径

- 状态：Accepted
- 日期：2026-08-22

## Context

执行引擎形态是最大的架构分叉点：纯解释器慢；自写机器码后端控制力强但成本极高；需要在 M3 前锁定主路径。

## Decision

双模式混合执行，同一对象模型：

1. **解释器常驻**：v0 不优化、正确性优先；服务 M0–M2 全部验收，并长期承担动态类加载/反射兜底职责（"动态特性变慢而不是失败"——对 native-image 的核心差异化）。
2. **AOT 主路径发射 Go 源码**：`classfile → IR → 构建期优化 → Go 源码 → go build`，closed-world 可达性分析；白嫖 Go 编译器的寄存器分配、内联、逃逸分析、BCE。
3. AOT 方法与解释器方法可互相调用，边界透明。

构建期优化优先级：CHA 去虚化/直接调用 → 内联 → lambda 脱糖 → 常量池固化 → intrinsic → 冗余 null check 删除 → 非逃逸 monitor 消除。

## Alternatives

- 纯解释器 + JIT（传统 JVM 路线）：放弃冷启动卖点，否决；
- v1 自写机器码后端：工期失控，推迟到 v2 议题（若 Go 源码路径触及吞吐天花板再评估）;
- 发射 C/C++/LLVM：破坏"纯 Go 工具链"故事与互操作卖点，否决。

## Evidence

先例支撑：GopherJS 验证了 Go 源码发射路线的可行性；jvm.go 验证了 Go 解释器承载 Java 语义的可行性；GraalVM native-image 验证了 closed-world AOT 的产品价值与反射配置痛点。定量证据待 M3 基准。

## Consequences

- 稳态吞吐受制于 Go 编译器保守优化（诚实预期写入 vision.md）；
- 发射产物为大量 Go 源码，整体编译时间是需要监控的指标；
- 解释器代码永久保留为一级公民，不是脚手架。

## Risks

Go 编译器对热点循环优化不足 → 卖点错位（启动/尾延迟/部署形态）+ v2 后端选项保留。

## Rollback

发射器是独立 pass；切换到自研后端只替换后端阶段，IR 与优化层复用。
