# ADR-0005: 异常实现机制延后至 M1 末，以调用约定抽象隔离

- 状态：Accepted（决策延后本身为决策）
- 日期：2026-08-22

## Context

Java 异常在 Go 侧有两种主流实现：panic/recover（正常路径零成本、异常路径较慢）与显式返回旗标（签名污染、正常路径多一次检查）。缺乏实测数据，人类指示延后决定。

## Decision

1. 机制选择延后至 **M1 结束前**，届时以数据裁决；
2. **隔离要求（立即生效）**：所有 AOT 发射代码的方法调用必须经过统一的调用约定抽象层（v0 可以只是固定样板生成），使切换机制不重写全量发射逻辑；
3. 解释器不受影响：解释器按异常表逐条处理，与所选机制正交；
4. 无论选哪种：Java 异常必须用**哨兵类型**承载，与普通 Go panic 严格区分，跨越 goroutine 边界与 runtime.Goexit 的行为需显式测试。

## Alternatives

- 现在拍板：违反 Evidence-before-opinion（协议 §1.3），否决。

## Evidence

计划于 M1 期间收集：挑热点方法手写双版本 Go 代码（panic/recover 版 vs 旗标版），纳入基准集，报告 median/p95。数据产出后本 ADR 更新为具体决策。

## Consequences

- 发射器从第一版起就带调用约定抽象层（轻微前期成本）；
- M1 验收不依赖该决策。

## Risks

抽象层泄漏（样板生成里混入机制特定代码）→ review checklist 检查项。

## Rollback

不适用（延后即回滚姿态）；机制定稿后以新 ADR 或本 ADR 修订记录。
