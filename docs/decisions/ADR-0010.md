# ADR-0010: AOT v1 采用统一对象表示，混合表示留作 v2 方法级优化

- 状态：Accepted
- 日期：2026-08-24
- 依据：R-0001 对象模型基准、R-0005 稳态吞吐报告、P-0006 判断一
- 关联：ADR-0004（收口）、ADR-0009（异常通道）、emitter-abi.md §3

## Context

P-0006 规划期预决策"v1 发射器采用统一表示（kernel.Instance）"，但该判断
挂有评审条件：发射器落地后须以实证复核，并正式收口 ADR-0004 的表示法
悬案。本 ADR 即该复核的结论。

## Decision

1. **v1 维持统一表示**：生成代码中一切引用值为
   `kernel.Instance/*JString/*ArrayObj`，与解释器共享同一对象空间；
2. **混合表示不废弃**：重定义为 v2 的方法级 accessor 内联方向——对已证实
   热点且字段布局稳定的具体类，生成强类型包装结构与内核桥接层；按方法
   粒度启用，准入条件与 ADR-0009 对 P 方案的纪律相同（基准证明 + 可回退）；
3. **表示法变更必须过 ADR**：任何绕过 emitter-abi §3 的布局实验视为架构
   变更。

## Rationale

- **正确性闭环优先**：双路径一致性验收的前提是零成本互操作；统一表示下
  混合执行无需桥接层。M3 验收（全 fixture + minimal-json 端到端逐字节
  一致）在该前提下达成；
- **瓶颈不在表示法**：R-0005 显示调用密集负载 AOT≈解释器（1.0–1.14×），
  共同瓶颈是运行时分发链（CallVirtual→InvokeAs→Native），不是字段访问
  或分派的对象布局。R-0001 的 5–11% 表示法差异被分发成本淹没；
- **ROI 排序**：单态内联缓存与 natives 直调（R-0005 优化方向 #1/#2）
  收益先于表示法重构。

## Consequences

- Emitted code 无法逃逸分析友好化——吞吐天花板由分发层决定，v2 内联时
  一并解决；
- kernel.Instance 布局成为跨引擎 ABI 的一部分，改动需回归全部 fixture。
