# ADR-0011: 互操作采用反射绑定为默认面，DefineClass 为逃生舱

- 状态：Accepted
- 日期：2026-08-24
- 依据：R-0008（能力审计、spike、调用税、设计空间分析）
- 关联：vision.md 卖点④；emitter-abi.md；P-0010（实施计划）

## Context

卖点④"Java↔Go 双向互操作（差异化最强）"至今零产品化。底层机制
（`DefineClass` + `NativeFunc`）经 60 个 bootstrap 类与 48 类 AOT 混跑
充分验证，但 embedder 必须手写描述符、Value 断言与槽语义——这是文档
缺失问题，不是机制缺失问题。

R-0008 spike 实证：
- 正确性：AOT 发射的 Java 调用 Go 注册函数（int/String/error 三形态）全部
  通过并钉扎（TestInteropFromAOT）；
- 调用税 **~82ns/次**，与虚调用 74ns 同量级——边界近乎免费，成本在注册期。

## Decision

1. **默认面 = 反射绑定** `internal/interop.Bind(k, spec)`：embedder 以 Go
   签名声明函数，注册期由 reflect 构建类型化 wrapper（闭包持有原函数，
   调用期零反射）；未支持类型**注册期 fail-fast**；
2. **逃生舱 = 原始 DefineClass** 保持公开——Bind 底层即它，全功率场景不设墙；
3. **v1 类型映射表固定**为 R-0008 §3.2（string/数值/bool/error/Value 透传），
   struct/slice/map 不映射并在注册期报错；扩展须经新 ADR；
4. **错误传播两级**：`error` 返回 → RuntimeException(msg)（v1）；Go panic →
   引擎错误（语义不变）；
5. **线程契约 v1 仅文档化**：同步调用、阻塞不可被 interrupt 唤醒（登记偏差）、
   异步走 embedder 自管 goroutine 的 fire-and-forget 模式。

## Alternatives

- **C 显式描述符助手**：比 B 可预测但仍是 Value 层编程，人体工学收益不足；
  其转换助手作为 Bind 内部实现自然存在。
- **立即做句柄注册表（struct/slice 映射）**：需求未经真实嵌入场景检验，
  过早抽象；v2 以真实反馈重开。

## Consequences

- 绑定类的方法解析发生在注册表，先于 classpath——编译期 stub 类可共存并被
  遮蔽（TestInteropFromAOT 场景钉扎）；
- ctx 池化要求 wrapper 在返回前完成对 CallContext 的全部读取（实现约束，
  P-0010 测试覆盖）；
- interop 已知限制（阻塞不可中断、类型集边界）进入 deviation-ledger 与文档。
