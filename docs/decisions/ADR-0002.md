# ADR-0002: 语言与字节码基线锁定 JDK 8（class file v52）

- 状态：Accepted
- 日期：2026-08-22

## Context

基线版本决定引擎需要实现的机制集合与 MVP 工期。现代基线（17/21）带虚拟线程叙事但机制面大；JDK 8 机制面最小且测试语料丰富。

## Decision

- 用户代码基线：`javac --release 8`，class file v52；
- lambda 在构建期脱糖为合成类（RetroLambda 同思路），运行期**不实现** indy/CallSite 机制；
- 字符串拼接按 JDK 8 语义处理为 StringBuilder 字节码；
- String 单后端 `[]uint16`（JDK 8 无 compact strings）；
- IR 与 classfile 解析模型从第一天起版本无关：版本差异只允许出现在前端 reader 与个别 pass。

## Alternatives

- JDK 21-first：虚拟线程叙事 + 新语法，但需运行期 indy 链接器（JEP 280 indy 拼接、库内 lambda）、condy(11)、nestmates(11)、模块(9)、record/sealed 属性——MVP 工期估计增加约 1/3；
- JDK 11-first：新增 nestmates/condy 却无虚拟线程收益，两头不占，否决。

## Evidence

机制差异为静态事实（JEP 280@9、254@9、181/309@11、模块@9）。"工期 -1/3"为推断而非实测，置信度 0.8；若 M0 实际进度证伪，回看本 ADR。

## Consequences

- 失去虚拟线程营销叙事（仅叙事损失：goroutine 底座不变，升级后补 Thread API 皮）;
- 现代生态库（Spring Boot 3 等）不可用 → demo 选 8 兼容版本（Jackson 2.x、Netty 4.1 等）;
- 升级到 17/21 为增量改造（预估 1–2 月）：indy 链接或库 jar 构建期脱糖、condy 构建期折叠、nest 访问检查、record 属性、String 双后端。

## Risks

升级成本被低估 → 以"IR 版本无关"硬约束兜底（见 architecture-rules.md R3）。

## Rollback

版本升级本身即本决策的预期演进路径；无需回滚，只需新 ADR。
