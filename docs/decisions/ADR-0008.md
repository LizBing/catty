# ADR-0008: 许可与 IP 姿态（Apache-2.0 主仓 + GPL 隔离 + provenance 纪律）

- 状态：Accepted
- 日期：2026-08-22

## Context

项目性质为学习/研究起步、保留产品化期权。许可决策具有高度不可逆性（先 GPL 后收紧几乎不可行），属协议 §19-E2 类决策，已获人类方向性确认。

## Decision

1. 主仓库整体 **Apache-2.0**；
2. GPL 材料（jtreg 子集等符合性测试）放**独立外部仓库**，永不进入主仓依赖树或二进制分发；
3. 一切非自写来源的代码必须逐文件登记 `PROVENANCE.md`（来源仓库、commit、许可证、甄别结论），L2 移植代码落地前完成（ADR-0006）;
4. 命名纪律：项目名 Catty；叙述用"Java 语言兼容运行时"，不做 TCK/兼容认证声明，不用 "Java" 作产品名主体；
5. 建立**语义偏差清单** `docs/specifications/deviation-ledger.md`：任何与 JVMS/JDK 8 规范行为的偏差必须登记，作为公开的信誉资产。

## Alternatives

- GPL 主仓：关闭未来商用与多数贡献者路径，否决；
- MIT：与 Apache-2.0 专利条款相比略弱，Apache-2.0 更契合"未来可能产品化"的定位；
- 暂不定 license：风险最大（后期换许可需全体贡献者同意），否决。

## Evidence

OpenJDK 为 GPL+CE；Harmony/libcore 谱系混杂需甄别（ADR-0006）；Apache-2.0 是生态兼容性与商用期权的主流平衡选择。

## Consequences

- 每次引入第三方代码多一道登记工序（由 review 强制）；
- deviation-ledger 成为持续维护义务。

## Risks

污染一旦发生清理成本极高 → 以"物理隔离 + review checklist + 未来 CI 许可扫描（debt 登记）"三层防御。

## Rollback

许可变更需新 ADR + 人类决策（E2）；本决策的目标正是保持该选项始终可行。
