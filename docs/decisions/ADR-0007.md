# ADR-0007: JNI/cgo 进入 v1 范围，M2.5 并行轨道分期落地

- 状态：Accepted
- 日期：2026-08-22

## Context

人类决定 JNI 进入 v1 范围。JNI 是调试黑洞且 cgo 破坏静态链接故事，需要范围与排序约束防止劫持主线。

## Decision

1. **排序**：M0–M2 保持纯 Go 不动摇；JNI 作为 M2.5 并行轨道启动，M3 收口；
2. **构建形态**：`jnion` 构建 tag，默认关闭；纯 Go 构建必须永远可用；
3. **技术映射**：
   - JNIEnv = 真实 C ABI 函数表（unsafe 布局对齐的函数指针结构），函数体为 Go 实现，回调分发回内核（AOT thunk 或解释器）；
   - local/global reference = 句柄表（索引句柄）：符合 JNI 语义并绕开 cgo 指针传递规则；Go GC 不移动对象，global ref 底层可直接持裸指针；
   - AttachCurrentThread：为原生线程起 `LockOSThread` 专用 goroutine，阻塞等待任务派发；
   - pending exception 协议：Env 结构上的挂起字段，边界处统一检查；
4. **v1 裁剪**：不支持 `GetPrimitiveArrayCritical` 等高危接口；目标为常见 JNI 库可加载运行。

## Alternatives

- v1 纯 Go、JNI 推 v2：被人类指令否决；
- JNI 进 M0–M2 主线：会吃掉解释器/AOT 工期，否决。

## Evidence

无定量证据；排序判断基于 JNI 调试成本的经验共识。若 M2.5 实际消耗超预估 2 倍，触发协议 §12 Scope Expansion 重议范围。

## Consequences

- 内核 API 从设计起需预留"被 C ABI 回调进入"的入口（可重入性）；
- JNI 桥是唯一允许 cgo 的位置（architecture-rules.md R1）。

## Risks

cgo 回调与 Go 运行时的交互问题集中爆发 → 限制在边界层，内核热路径零 cgo。

## Rollback

构建 tag 默认关即事实回滚；桥代码可整目录移除而不伤内核。
