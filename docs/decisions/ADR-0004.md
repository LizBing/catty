# ADR-0004: 对象模型采用"具体类型 + 接口"混合表示（暂定）

- 状态：Provisional — 方向已获证据支持（R-0001），综合置信度 0.72 < 0.8 转正门槛；M3 发射器动工前按收口条件定稿
- 日期：2026-08-22（证据更新：2026-08-23）

## Context

引用对象的 Go 表示法决定 AOT 产物形态与性能上限，是最难回滚的内部决策之一。两个候选：一切皆 `*Object`（统一、简单）；具体结构体 + embedding 继承链 + 接口提升（类型信息丰富）。

## Decision（暂定）

混合表示：

- Java 类 → Go 结构体，embedding 镜像继承链；公共头部 `{cls *ClassInfo, monitor *Monitor(惰性), hashCode uint32(惰性)}`；
- 身份语义 = Go 指针相等；数组 = 定长结构体包裹；
- 表达式静态类型取可证明的最窄类型；不足以分派时提升为 Go interface，走 itab 动态分派（≈ 虚调用）；CHA 收窄处为直接调用——去虚化由类型系统自然涌现；
- 字段遮蔽用限定选择器显式表达（Java 字段不覆写）；
- 该约定隔离在发射器调用约定抽象层内，切换表示法不重写全量发射逻辑。

## Alternatives

- 统一 `*Object` 表示：实现简单、解释器友好，但分派靠类型断言；
- （R-0001 讨论过的第三方案 C：代码生成伪 vtable——成本高且收益与 A 重叠，未实现，见报告 Unknowns。）

## Evidence

**P-0002 / R-0001 微基准（2026-08-23，Apple M1，手工中位数，三轮方向一致）：**

| 组 | 结论 |
|---|---|
| 单态调用 | A 快 ~5%（D6 持平） |
| 双态调用 | 噪声内持平（B 的 2 路 switch 可内联成比较链） |
| 兆态调用 | A 快 ~6% / ~11%（8 路 switch 无法内联） |
| 字段读写 | 完全持平（两者编译为同等定偏移访问） |
| 下行转换 | 持平 |

方向置信度 ~0.9（A 从不稳定更慢，兆态优势随深度扩大）；"据此转 Accepted"的综合置信度 **0.72 < 0.8 门槛**：合成微基准未覆盖真实字节码负载与发射器交互。

**本实验修正的两处原始论据（据 R-0001 更正）：**
1. ~~"字段访问零装箱是 A 的优势"~~ ——字段访问两案持平；A 的真实差异点在分派路径；
2. ~~"统一表示阻断逃逸分析"~~ ——B 的固定数组同样栈分配；A 的结构性收益是可证明类型处的 interface 去虚化+内联（`-m`: `devirtualizing a.Compute to *D3Leaf`）。

## Consequences

- 若成立：兆态/单态分派占优，去虚化免费获得；实现复杂度高于 B；
- 结构体布局变更波及所有发射代码 → 发射器集中管理布局映射。

## Risks

微基准→真实负载的外推风险（剩余不确定性的主要来源）。

## 收口条件（替代原"补实验"的模糊表述）

满足其一即可定稿：
1. M3 发射器以调用约定抽象层双模式运行真实 fixture，端到端对比无反转且 A 不劣 → Accepted；
2. 出现反证（真实负载 B 显著占优）→ Superseded 并记录数据。
在此之前，全部设计与文档按方案 A 推进（工作假设），发射样板保持约定隔离。

## Rollback

退回统一 `*Object` 表示（解释器路径本就以它起步），发射器调用约定层吸收差异；本 ADR 改为 Superseded 并附数据。
