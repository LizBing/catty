# ADR-0004: 对象模型采用"具体类型 + 接口"混合表示（暂定）

- 状态：Provisional — 等待 P-0002 微基准证据裁决；M3 发射器动工前必须定稿
- 日期：2026-08-22

## Context

引用对象的 Go 表示法决定 AOT 产物形态与性能上限，是最难回滚的内部决策之一。两个候选：一切皆 `*Object`（统一、简单）；具体结构体 + embedding 继承链 + 接口提升（类型信息丰富）。

## Decision（暂定）

混合表示：

- Java 类 → Go 结构体，embedding 镜像继承链；公共头部 `{cls *ClassInfo, monitor *Monitor(惰性), hashCode uint32(惰性)}`；
- 身份语义 = Go 指针相等；数组 = 定长结构体包裹；
- 表达式静态类型取可证明的最窄类型；不足以分派时提升为 Go interface，走 itab 动态分派（≈ 虚调用）；CHA 收窄处为直接调用——去虚化由类型系统自然涌现；
- 字段遮蔽用限定选择器显式表达（Java 字段不覆写）；
- 该约定隔离在发射器调用约定抽象层内，切换表示法不重写全量发射逻辑。

## Alternatives

- 统一 `*Object` 表示：实现简单、解释器友好，但在发射路径上到处类型断言，阻断 Go 编译器经接口的内联与逃逸分析；
- 全 interface 表示：分派开销最大化，否决。

## Evidence

**尚无实测证据**。裁决实验已立计划：docs/plans/active/P-0002-object-model-microbenchmark.md（继承链深度、单双态调用点、字段访问、接口断言四组微基准，benchstat，n≥10）。当前置信度 0.65，低于协议 §19-E7 的重大决策门槛——故标记 provisional 并用"约定隔离"降低不可逆性，而非阻塞 M0/M1（解释器阶段两种表示法差异不影响正确性验收）。

## Consequences

- 若成立：去虚化/直接调用免费获得，字段访问零装箱；
- 结构体布局变更会波及所有发射代码 → 发射器必须集中管理布局映射。

## Risks

embedding 链过深导致 Go 编译器选择器解析变慢或内联预算耗尽 → 由 P-0002 数据检验。

## Rollback

P-0002 数据不利时：退回统一 `*Object` 表示（解释器路径本就以它起步），发射器调用约定层吸收差异；本 ADR 改为 Superseded 并记录数据。
