# Gate 5 implementation-agent prompt

Implement Catty Gate 5 on `codex/gate-5`, starting from the planning commit on that branch. Deliver the opt-in `--enable-lifecycle` profile, application shutdown and diagnostics, and reproducible application measurements. Read [GATE5.md](GATE5.md), [GATE5-TESTING.md](GATE5-TESTING.md), [architecture §§8–11](ARCHITECTURE.md#8-application-startup-fallback-and-exit), and the [Gate 4 termination follow-ups](../out/gate4/EVIDENCE.md#second-follow-up-wait-set-retention-and-overflow-deadlines).

1. Verify the active branch and existing changes. Start with the profile, generated launcher, and bootstrap admission. Keep Gates 2–4 selectable and keep the AOT, interpreter, reflection, and late-plugin paths on the shared Java calling convention.
2. Implement the lifecycle state transitions around `rt/launcher.go`, `rt/thread_java.go`, and the Gate 5 bootstrap intrinsics. Use deterministic tests for first-zero shutdown, registry freeze, exit contention, and halt. In particular, a blocked main or exit caller must not prevent the launcher from acting on a terminal result. Preserve monitor ownership and Java frames of successful exit and halt callers until process termination.
3. Implement process trace events, named-thread and host-fault diagnostics, and opt-in metrics. Check ordering and data races in actual generated executables, including a trace sealed while ordinary Java threads are still live.
4. Implement the differential suite and benchmark runner. Use OpenJDK 21 to resolve observable semantic questions. Record an intentional profile policy when the Java API leaves an outcome unspecified or a JDK-specific behavior varies. Run the Gate 5 suite and the Gate 1–4 regressions, then record four-mode measurements against the same class files and inputs.
5. Update the usage documentation for the implemented profile. Leave the code, fixtures, runners, and `out/gate5/EVIDENCE.md` on `codex/gate-5`. In your handoff, provide the branch and commit IDs, exact validation commands with outcomes, key measurement results, and any unresolved behavior or environment limits. Distinguish measured results from observations based on a smoke run.

The planning baseline is `b29949a`, which contains the Gate 4 timer, peer-monitor termination, wait-set retention, and overflow-deadline corrections. A planning probe on Temurin OpenJDK 21.0.13.1+2 observed that a terminated hook peer can be registered, null add/remove fail with `NullPointerException` while running and `IllegalStateException` after registry freeze, `System.exit(-3)` runs hooks and reports POSIX status `253` without executing the caller's `finally`, `halt(19)` skips hooks, uncaught main and hook errors preserve status `1`, and calling exit from a hook can stall shutdown. Turn these into checked-in acceptance cases where specified.
